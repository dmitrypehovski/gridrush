# GRIDRUSH RSI — what actually worked (best = `gen_6.py`)

**Result: score 279.91 vs 190.22 for `gen_0.py` (+47.1%); vs the original 202.40 (loop.json snapshot 04:24) +38.3%; vs the live loop-best 185.18 +51.2%. 32 flex sites, violations 0, compliant_mwmonths == delivered_mwmonths.**
The gain came not from tuning 9 parameters but from an exact model: the score is additive across 8 substations (headroom is the only thing they share), so the problem can be solved exactly. A substation's capacity splits into 3 price tiers: 99.99% ×1.25 (the MW that run in every hour, ≤ min H), 99.9% ×1.0 (≤ the 8th worst hour), 99% ×0.8 (≤ the 87th) — the tiers go to the sites with the earliest T_flex. Then a DP over MW prefixes (a site's price depends only on the accumulated prefix, avail = 1 − #{H < P}/8760) gives the exact optimum: gen_4 was a bug (candidates were breakpoints only → an empty portfolio on S02), gen_5 was already 277.1, gen_6 closes another 2.8 via repair-compatible MW.
**What did not work (honestly):** (1) batteries as a way to break through min-headroom — the verifier in `sim/engine.py` counts battery-covered load as substation load, so any deficit = violations (700 MWh, score −6737); (2) firm as a "premium without curtailment" — T_firm 18–36 vs T_flex 5–10 at the same ×1.25, strictly dominated by flex@99.99%; (3) coordinate ascent from a greedy start — it gets stuck in a coordination optimum (you need to move MW between two sites at once), and only the tier decomposition helped; (4) `repair_portfolio` is not harmless: its asymptotic binary search shaves 0.01 MW off every site and drops sites sitting exactly at 0.50 MW — fixed with an offset of +0.0049.
**The rule the agent learned about the model:** the whole business is a queue for low-headroom hours, and the SLA is the price of a place in that queue; you buy the ×1.25 premium where min(H) has not been reached yet, and everything above sells at 0.8 and is still profitable, because otherwise those MW do not sell at all.
