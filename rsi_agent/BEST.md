# GRIDRUSH RSI — что реально сработало (best = `gen_6.py`)

**Итог: score 279.91 vs 190.22 у `gen_0.py` (+47.1%); против исходного 202.40 (снапшот loop.json 04:24) +38.3%; против живого loop-best 185.18 +51.2%. 32 flex-сайта, violations 0, compliant_mwmonths == delivered_mwmonths.**
Прирост дало не тюнингование 9 параметров, а точная модель: score аддитивен по 8 подстанциям (общий у них только headroom), поэтому задачу можно решить точно. Ёмкость подстанции раскладывается на 3 ценовых слоя: 99.99% ×1.25 (MW, которые идут в каждый час, ≤ min H), 99.9% ×1.0 (≤ 8-й худший час), 99% ×0.8 (≤ 87-й) — слои отдаём сайтам с самым ранним T_flex. Затем DP по префиксам MW (цена сайта зависит только от накопленного префикса, avail = 1 − #{H < P}/8760) даёт точный оптимум: gen_4 был багом (кандидаты только брейкпоинты → на S02 пустой портфель), gen_5 уже 277.1, gen_6 закрывает ещё 2.8 через repair-совместимые MW.
**Не сработало (честно):** (1) батареи как способ пробить min-headroom — verifier в `sim/engine.py` считает покрытую батареей нагрузку нагрузкой подстанции, поэтому любой дефицит = violations (700 MWh, score −6737); (2) firm как «премиум без куртейлмента» — T_firm 18–36 против T_flex 5–10 при том же ×1.25, строго доминируется flex@99.99%; (3) координатный подъём из жадного старта — застревает в coordination-оптимуме (нужен перенос MW между двумя сайтами сразу), помогло только tier-разложение; (4) `repair_portfolio` не безобиден: его асимптотический бинарный поиск срезает 0.01 MW с каждого сайта и выбрасывает сайты ровно на 0.50 MW — лечится офсетом +0.0049.
**Правило, которое агент выучил про модель:** весь бизнес — это очередь за низкими часами headroom, и SLA это цена за место в очереди; покупать премию ×1.25 надо там, где min(H) ещё не достигнут, а всё, что выше, продаётся за 0.8 и всё равно выгодно, потому что иначе эти MW не продаются вообще.
